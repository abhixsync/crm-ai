Real-Time Architecture

SSE + Redis Pub/Sub — how events flow from DB write to browser

── WRITE PATH (existing endpoints) ──────────────────
POST /customers
→
PATCH /customers/[id]
→
DELETE /customers/...
↓ (after DB write, already calls invalidateCache)
+ publishEvent("tenant:{id}", {type:"metrics:update"})
── EVENT BUS ─────────────────────────────────────────
src/lib/events/event-publisher.ts
publishes to
Redis Pub/Sub channel
channel: "realtime:{tenantId}"
── READ PATH (new SSE endpoint) ─────────────────────
Redis Pub/Sub
→
GET /api/events (SSE)
→
browser EventSource
streams: metrics:update, notification:new, call:status
── BROWSER (client hooks) ────────────────────────────
useSSE() hook
→ on "metrics:update" →
dashboard re-fetches /api/dashboard/metrics
useSSE() hook
→ on "notification:new" →
shell re-fetches unread count

Events

Event type Triggered by Browser reaction
metrics:update Any customer write Dashboard refetches metrics
notification:new New InAppNotification created Bell badge count updates
call:status Call webhook / status change Dashboard "active calls" refreshes
