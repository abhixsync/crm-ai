AI Credits — System Architecture

3 approaches to building the credit engine. Pick one to proceed to full design.

1

Extend UsageRecord Minimal change

Add credit fields to the existing UsageRecord model. No new models.

✓ Least code — extends existing pattern
✓ No schema migration complexity
✗ UsageRecord is monthly-scoped — purchased credits (cross-month) don't fit
✗ No transaction history — can't audit "who spent what when"
✗ Reserve+settle becomes messy in a single row
New fields on UsageRecord: creditsUsed, creditsReserved
New model: CreditPurchase (one row per top-up)
2

Event-Sourced Ledger Most accurate

Every credit event (grant, spend, reserve, settle, purchase, expire) is an immutable row. Balance = sum of all entries.

✓ Perfect audit trail — every credit accounted for
✓ Handles all edge cases naturally
✓ Replay-safe, never gets out of sync
✗ Balance requires summing all rows — slow at scale
✗ Over-engineered for current scale
New models: CreditLedgerEntry (type, amount, tenantId, callLogId, meta)
Balance computed on read — no denormalized total field
3

Balance + Transaction Log ⭐ Recommended

One balance row per tenant (fast reads). Append-only transaction log for audit trail.

✓ Fast balance reads — single DB row for plan-guard checks
✓ Full audit trail for billing disputes
✓ Reserve+settle maps cleanly to reservedCredits field
✓ Clean separation: plan credits vs purchased credits
✗ Balance + log must stay in sync (use DB transactions)
TenantCreditBalance: planCredits, purchasedCredits, reservedCredits, usedThisMonth
CreditTransaction: type, amount, callLogId, meta, createdAt (append-only)
CreditPack: SUPER_ADMIN configurable packs (name, credits, priceInr, priceUsd, isRecurring)
CreditPackPurchase: tenant purchases — one-time + recurring subscriptions

Credit flow for a single AI call (Approach 3)

1. PRE-CALL Check available = planCredits + purchasedCredits - reservedCredits ≥ reserveAmount (configurable, default 20). Block if not enough. 2. RESERVE reservedCredits += 20. Log: RESERVE transaction. Call proceeds. 3. CALL ENDS Webhook receives durationSecs. actual = 2 + ⌈durationSecs / 60⌉ 4. SETTLE reservedCredits -= 20. Deduct actual from planCredits first, then purchasedCredits. Log: SETTLE transaction with callLogId. 5. MONTHLY Cron resets planCredits to plan allocation. purchasedCredits untouched. Log: MONTHLY_GRANT.
