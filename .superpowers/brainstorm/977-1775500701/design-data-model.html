Design — Section 1: Data Model

4 new models + small additions to existing ones. Approve before we move to Section 2.

New Models

TenantCreditBalance One row per tenant — fast balance reads for plan-guard checks
planCredits Int — monthly grant, resets each cycle
purchasedCredits Int — from top-ups, persists
reservedCredits Int — held during active calls
usedThisMonth Int — for display only
planResetAt DateTime — last monthly reset
Available balance formula: planCredits + purchasedCredits − reservedCredits
CreditTransaction Append-only audit log — one row per credit event
type enum (see below)
amount Int (+credit / −debit)
balanceAfter Int snapshot for display
callLogId FK → CallLog (RESERVE/SETTLE)
idempotencyKey Unique — prevents double-deduction
meta JSON — provider, duration, etc.
Types: MONTHLY_GRANT RESERVE SETTLE PURCHASE SUBSCRIPTION_GRANT EXPIRE ADJUSTMENT REFUND
CreditPack SUPER_ADMIN configures
name "Starter Pack"
credits Int — granted on purchase
priceInr / priceUsd Decimal
isRecurring Boolean — add-on vs one-time
stripePriceId / razorpayPlanId
isActive, sortOrder
CreditPackPurchase Per purchase record
tenantId, packId
creditsGranted Int snapshot
amountInr / amountUsd
billingProvider STRIPE | RAZORPAY
status PENDING/COMPLETED/FAILED/REFUNDED
expiresAt null = never expires

Changes to existing models

PlanDefinition
+ creditsPerMonth Int
Replaces maxAiCallsPerMonth logically. Keep old field for backward compat, set to -1.
CallLog
+ creditsReserved Int?
+ creditsCharged Int?
Track per-call credit usage for reconciliation.
SubscriptionConfig
+ credit_init_fee (2)
+ credit_per_minute (1)
+ credit_reserve_amount (20)
+ credit_low_warning_pct (20)
+ credit_purchased_expiry_days (365)
