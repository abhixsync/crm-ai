Design — Section 2: Credit Lifecycle

How credits flow through every event in the system. Confirm to move to Section 3.

Full lifecycle map

1 — TENANT CREATED (registration)
createTrialSubscription() also calls createCreditBalance(tenantId, PRO_credits)
Creates TenantCreditBalance with planCredits = PRO.creditsPerMonth, planCreditsAllocated = same, planResetNextAt = trialEndsAt
2 — CALL TRIGGERED (pre-call)
Step A Read balance: available = planCredits + purchasedCredits − reservedCredits Step B Check available ≥ credit_reserve_amount (config, default 20). Block with 402 if not. Step C Atomic reserve: UPDATE ... SET reservedCredits += 20 WHERE available ≥ 20. Zero rows = race condition caught, block. Step D Log RESERVE transaction. Key: reserve-{callLogId}. Write CallLog.reservedAt = now() and creditsReserved = 20.
3A — CALL COMPLETED (webhook settles)
Step A Receive durationSecs from Twilio/Vonage status webhook Step B Compute: actual = credit_init_fee + ⌈durationSecs / 60⌉ (e.g. 95s → 2 + 2 = 4 credits) Step C Deduct order — plan credits first, then purchased: if planCredits ≥ actual → deduct all from plan. Else → deduct remaining from purchasedCredits. Step D In one DB transaction: reservedCredits -= 20, deduct actual, increment planCreditsUsedThisMonth, update CallLog.creditsCharged. Step E Log SETTLE transaction. Key: settle-{callLogId}. Idempotent — webhook retry is a no-op.
3B — CALL FAILED / NO-ANSWER (full refund)
Status = FAILED, BUSY, or NO_ANSWER from webhook. No credits charged.
reservedCredits -= 20 (full release). Log REFUND transaction. Key: settle-{callLogId} (same key — idempotent). CallLog.creditsCharged = 0.
3C — STALE RESERVE (cron cleanup)
Cron finds: CallLog WHERE creditsReserved > 0 AND creditsCharged IS NULL AND reservedAt < now() − credit_reserve_timeout_hours
Auto-settles with durationSecs = 0 → charges only initiation fee (2 credits). Logs SETTLE with meta: auto_settled_timeout: true. Prevents permanent credit lock.
4 — CREDIT PURCHASE (one-time or recurring)
Stripe/Razorpay webhook fires with metadata.purchaseType = "credit_pack"
In one transaction: create CreditPackPurchase (status=COMPLETED), increment purchasedCredits, log PURCHASE transaction. Key: purchase-{providerTxId}.
Recurring add-on: same flow on each renewal. Updates nextRenewalAt, increments renewalCount. Status stays ACTIVE_RECURRING.
5 — MONTHLY RESET (cron)
Check Only run if planResetNextAt ≤ now() — idempotency guard. Key: monthly-{tenantId}-{YYYY-MM}. Reset Set planCredits = plan.creditsPerMonth, planCreditsUsedThisMonth = 0, planResetAt = now(), planResetNextAt = next cycle. Safe reservedCredits is NOT touched — in-flight calls are unaffected. purchasedCredits untouched. Log MONTHLY_GRANT transaction. If credit_purchased_expiry_days > 0, run expiry check on old CreditPackPurchases.
6 — LOW CREDIT WARNINGS (async, non-blocking)
After every SETTLE, check available / planCreditsAllocated:
≤ 20% → in-app banner (amber) + email to ADMIN. ≤ 5% → in-app banner (red) + second email.
Campaigns: credit check runs per-call in automation runner. On first failure → set campaign PAUSED, reason = INSUFFICIENT_CREDITS. Resume is manual after top-up.
