Data Model v2 — Revised after adversarial review

4 critical + 5 major issues found and fixed. Scroll to see all changes.

What was broken (critical issues)

C1 — Concurrent calls would overdraw. Two calls firing at once both pass the credit check before either reserves. Fix: atomic UPDATE with WHERE clause — zero rows affected = block.
C2 — Wrong pool gets debited. Plan credits should be spent first (they reset anyway). Without tracking which pool was drawn, purchased credits get consumed and plan credits reset unused. Fix: add planCreditsUsedThisMonth field + always deduct plan credits first.
C3 — Two competing limit systems. Existing assertCanMakeAiCall() still enforces maxAiCallsPerMonth and would block tenants who bought extra credits. Fix: deprecate maxAiCallsPerMonth (set -1 in seed), replace assertCanMakeAiCall() with credit check.
C4 — Reserved credits leak forever. In local dev (no HTTPS), webhooks never fire. Reserve stays locked forever. Fix: cron auto-settles stale reserves older than configurable timeout (default 2h).

Edge cases now explicitly handled

New tenant signup — createTrialSubscription() also creates TenantCreditBalance with PRO-level credits
Plan downgrade — downgradeToFree() does NOT zero purchasedCredits
SUPER_ADMIN calls on behalf of tenant — debits that tenant's credits, not bypassed
Failed/no-answer calls — initiation fee NOT charged; full reserve returned as REFUND
Webhook handler conflict — Stripe webhook checks metadata.purchaseType before routing to plan upgrade vs credit grant
Monthly reset race — settlement always releases from reservedCredits, never from the live pool; reset is safe at any time
Campaign mid-credit-exhaustion — automation runner checks credits per call; sets campaign to PAUSED with reason INSUFFICIENT_CREDITS
Pack deactivated with active recurring subs — existing purchases are grandfathered; snapshots creditsAtPurchase + priceAtPurchase protect them
