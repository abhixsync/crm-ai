Design — Section 3: APIs + UI

New endpoints, changes to existing ones, and UI surfaces. Confirm to move to Section 4: Plan Defaults.

New API endpoints

Tenant (ADMIN)
GET/api/credits/balance — balance, reserved, reset date, used this month
GET/api/credits/transactions — paginated history, filterable by type
GET/api/credits/packs — available packs (active only)
POST/api/billing/credits/checkout — create Stripe/Razorpay checkout for a pack
POST/api/billing/credits/cancel-recurring — cancel recurring add-on
SUPER_ADMIN
GETPOST/api/admin/credit-packs — list + create packs
PUTDEL/api/admin/credit-packs/[id] — edit / deactivate
POST/api/admin/credits/adjust — manually grant/deduct credits for any tenant
GET/api/admin/credits/[tenantId] — view any tenant's credit balance

Changes to existing endpoints

POST /api/calls/trigger
Remove: guard.assertCanMakeAiCall()
Add: creditService.reserveCredits(tenantId, callLogId) — atomic reserve, throws 402 if insufficient
POST /api/calls/status (Twilio/Vonage status webhook)
Add: On COMPLETED → settleCredits(tenantId, callLogId, durationSecs)
Add: On FAILED/BUSY/NO_ANSWER → refundReserve(tenantId, callLogId)
POST /api/billing/stripe/webhook
Add: Check session.metadata.purchaseType:
"plan_subscription" → existing upgradePlan() flow "credit_pack" → new grantPurchaseCredits() flow
POST /api/billing/razorpay/webhook — same purchaseType routing as Stripe
POST /api/cron/subscription-expiry
Add 3 steps: releaseStaleReserves() → expirePurchasedCredits() → grantMonthlyCredits() for all due tenants
